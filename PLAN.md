# PLAN.md: Builder Implementation Plan

## Objective
Build and package **Jitter GPS Desktop**, a cross-platform desktop application (macOS & Windows) that hooks into Chrome/Edge/Brave via Chrome DevTools Protocol (CDP) to inject randomized, non-repeating GPS coordinates within a user-defined radius.

---

## File Structure to Implement
```
jitter-gps-desktop/
├── PRD.md                 # Product requirements & technical specification
├── PLAN.md                # This task blueprint & handoff instructions
├── requirements.txt       # Dependencies (requests, websockets, customtkinter)
├── core/
│   ├── __init__.py
│   ├── jitter_engine.py   # Uniform disc math + collision filter
│   ├── browser_finder.py  # Cross-platform binary locator (macOS & Windows)
│   └── cdp_client.py      # CDP WebSocket driver (setGeolocationOverride)
├── ui/
│   ├── __init__.py
│   └── app_window.py      # Desktop GUI (CustomTkinter dark mode)
├── main.py                # Application entrypoint
└── build.py               # PyInstaller packaging script (.app / .exe)
```

## Ordered Implementation Tasks

### Phase 1: Core Modules
- [ ] **Task 1: `core/jitter_engine.py`**
  - Implement `JitterEngine` class with `generate_unique_coord(center_lat, center_lng, radius_m)`.
  - Implement uniform disc random distribution ($r = R \sqrt{u}, \theta = 2\pi v$).
  - Maintain `seen_coords = set()` formatted to 6 decimal places.
  - Compute haversine or planar distance for verification log.
  - Self-check: Run unit test generating 1,000 points; assert `len(seen) == 1000` and all points $\le \text{radius}$.

- [ ] **Task 2: `core/browser_finder.py`**
  - Implement `get_browser_executable(preferred='chrome')` supporting `darwin` and `win32`.
  - macOS candidates:
    - `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`
    - `/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge`
    - `/Applications/Brave Browser.app/Contents/MacOS/Brave Browser`
  - Windows candidates:
    - `C:\Program Files\Google\Chrome\Application\chrome.exe`
    - `C:\Program Files (x86)\Google\Chrome\Application\chrome.exe`
    - `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`
  - Implement `launch_browser_with_cdp(port=9222, browser_type='chrome')`.

- [ ] **Task 3: `core/cdp_client.py`**
  - Fetch target page sessions from `http://127.0.0.1:<port>/json/list`.
  - Filter `type == 'page'` and obtain `webSocketDebuggerUrl`.
  - Implement asynchronous or threaded socket sender calling `Emulation.setGeolocationOverride`.
  - Implement `clear_geolocation_override()`.

### Phase 2: User Interface (`ui/app_window.py`)
- [ ] **Task 4: Main GUI Layout**
  - Build responsive dark window using `customtkinter` (fallback to `tkinter`).
  - Input Grid: Latitude, Longitude, Radius (m), Update Interval (s).
  - Quick action: "Fetch Current IP Location" button via `ipapi.co/json`.
  - Control buttons:
    - `Launch Debug Browser`
    - `Start Spoofing` / `Stop Spoofing` (color toggle)
  - Activity log pane: Multi-line text widget showing real-time spoof events:
    `[HH:MM:SS] Applied -> Lat: -6.208123, Lng: 106.845912 (Offset: 124m)`

- [ ] **Task 5: Worker Thread & State Management**
  - Decouple GUI from WebSocket communication via background worker (`threading.Thread`).
  - Periodically pull targets and dispatch new coordinate generated by `JitterEngine`.
  - Gracefully handle closed tabs or browser shutdowns.

### Phase 3: Packaging & Build System
- [ ] **Task 6: Entrypoint & PyInstaller Configuration (`build.py`)**
  - macOS build: `pyinstaller --noconsole --name="JitterGPS" --windowed main.py`.
  - Windows build: `pyinstaller --noconsole --name="JitterGPS" --onefile main.py`.

---

## Acceptance Criteria
1. Launching the debug browser from the app opens Chrome/Edge on port `9222`.
2. Visiting `https://browserleaks.com/geo` in the launched browser shows coordinates matching the app log.
3. Over 10 consecutive ticks, 10 different coordinate pairs are returned within the defined radius.
4. Stopping spoofing clears overrides and restores normal location.
